READ THIS FIRST

This document is the single source of truth for building the Sahajomy
Flutter mobile app. It defines all architecture, UI, API, and feature
requirements based on the current web platform and FastAPI backend.

The backend at /api/v1 is authoritative for:
- Business logic, pricing, payments, RBAC, validation
- Status transitions, workspace isolation, tenant ownership
- All mutation outcomes (bookings, intakes, collections, etc.)

Do not re-implement any business rule in the mobile layer.

3.  AUTHENTICATION & ONBOARDING
─────────────────────────────────────────────────────────────────────────

3.1  Flow
     1. Splash → read secure storage → GET /auth/me
     2. OTP send/verify → POST /auth/send‑otp / /verify‑otp
     3. MFA (privileged roles) → authenticator QR + manual secret
     4. Load workspaces → GET /workspaces
     5. Navigate to role shell
     6. Logout → POST /auth/logout → clear storage

3.2  Token Storage
     Use flutter_secure_storage with keys:
       access_token
       refresh_token
     Save/restore atomically. Never log tokens.

3.3  Refresh Mechanism
     ─ On 401, pause all pending requests
     ─ Issue one refresh request at a time
     ─ Update tokens in secure storage
     ─ Replay all paused requests with new token
     ─ If refresh fails → clear tokens → route to login

3.4  MFA Implementation
     ─ Show QR code for authenticator apps
     ─ Provide manual secret as fallback
     ─ Validate 30‑second rolling codes
     ─ Handle refresh race conditions (prevent duplicate MFA)

4.  ROLE‑BASED NAVIGATION & DEEP LINKS
─────────────────────────────────────────────────────────────────────────

4.1  Bottom Navigation (4 or 5 tabs)

     Customer         │ Home, Shipments, Agizisha, More
     Cargo Company    │ Bookings, Containers, Receipts, Account
     Sourcing Agent   │ Home, Batches, Orders, More
     Super Admin      │ Home, Users, Activity, More

     Cargo Company NEVER shows public Home/landing.

4.2  Workspace Switching
     ─ Account role remains stable across workspaces
     ─ Company workspace provides company role, branch, permissions
     ─ Send X‑Sahajomy‑Company and optional X‑Sahajomy‑Branch headers
     ─ Clear old tenant state BEFORE navigating to new workspace

4.3  Deep Links (App Links)
     Supported URIs:
       sajajomy://customer/warehouse‑access/:token
       sajajomy://shared/label/air/:bookingId
       sajajomy://shared/label/sea/:seaBookingId
       sajajomy://shared/product/:productId
       sajajomy://shared/batch/:token
       sajajomy://verify‑receipt/:code

     Rules:
       ─ Always verify role before navigating
       ─ If unauthenticated, store destination and resume after login
       ─ Never log the token/code
       ─ Reject destinations that don't match user's role

6.  WAREHOUSE AUTOMATION – CRITICAL FLOWS
─────────────────────────────────────────────────────────────────────────

6.1  Customer Warehouse Access
     1. Scan opaque warehouse access QR
     2. Authenticate (if needed) and resume app link
     3. Fetch only current customer's parcels for that warehouse
     4. Enable selection only when `eligible_for_collection` is true
     5. Submit collection request (one or more intake UUIDs)
     6. Display returned collection QR + PIN with expiry countdown
     7. Never expose a "mark collected" button

6.2  Cargo Admin Scanning & Intake
     1. Check automation status (GET /automation/status)
     2. Manual Cargo Intake remains available in all modes
     3. Scan barcode/QR or choose a label image
     4. Show manual text entry immediately as fallback
     5. Render high/medium/low confidence
     6. Staff confirms → create intake/parcel
     7. Link to booking → update Shipment Order tracking/location/status
     8. Notify customer
     9. Loading scans: detect wrong booking / duplicate / already‑loaded
     10. Milestones: update tracking & Shipment Order state

     Important:
       ─ Never silently confirm medium/low‑confidence suggestions.
       ─ Confirmation is a deliberate staff action.
       ─ Treat 409 (duplicate/conflicting) and 410 (expired) without retry.

6.3  Super Admin Entitlement
     ─ List Cargo Admins with automation enabled/disabled
     ─ Enable/disable with PUT /super_admin/warehouse‑automation/...
     ─ No billing logic – just toggle the flag.

7.  SEA & AIR BOOKING STATE MACHINE (Shared Shell)
─────────────────────────────────────────────────────────────────────────

Both Customer and Sourcing Agent use the same three‑step shell.

  Step 1: Choose Service
    ─ Show three recommendations first.
    ─ "Browse all" → search + incremental loading.
    ─ Works with 1,000+ services (paginated).

  Step 2: Cargo Details
    ─ Mode‑specific fields (Sea vs Air).
    ─ Only fields required by selected cargo mode.
    ─ For Sea, show operator's China address (pre‑fetched).
    ─ For Air, show provider‑scoped delivery details.

  Step 3: Review
    ─ Complete summary.
    ─ For Customer Sea: show shipping mark + link to "My China Addresses"
      instead of duplicating full saved address.
    ─ "Continue to review" does NOT create a booking – it's local validation.
    ─ Final "Confirm booking" performs the mutation.
    ─ Prevent duplicate confirmation while in flight.
    ─ After success, show authoritative reference and View booking button.

  Deep‑link handling:
    ─ If a container_id, cargo_admin_id, or warehouse_id is provided,
      resolve it and restore the appropriate selection.
    ─ If stale/inaccessible, return to Step 1 with a clear message.

     ─ Buttons: 52‑56px high, min tap area 48px
     ─ Inputs: 48‑52px high, label above, validation below

8.5  Accessibility

     ─ 48px touch targets
     ─ Semantic labels and focus order
     ─ 200% text scaling support
     ─ QR/PIN screens: provide text alternative; secrets announced only on request

9.  API INTEGRATION NOTES
─────────────────────────────────────────────────────────────────────────

9.1  Error Handling
     Map each FastAPI status to a user‑actionable message:
       401  → Session expired → redirect to login
       403  → Permission denied → show upgrade/contact
       409  → Conflict → show conflict message, no retry
       410  → Expired → request new link
       422  → Validation → show field‑specific errors
       429  → Rate limited → show backoff message

9.2  Idempotency Keys
     ─ Send for all mutation requests (booking, intake, collection, etc.)
     ─ Prevent duplicate submissions.
     ─ Handle power/internet interruptions gracefully.

9.3  Never Log
     ─ OTP codes
     ─ JWTs (access/refresh tokens)
     ─ Collection PINs
     ─ Warehouse access tokens
     ─ Decrypted phone/email data
     ─ Uploaded label images

9.4  Context Headers
     ─ X‑Sahajomy‑Company   (required for company context)
     ─ X‑Sahajomy‑Branch    (optional)
     ─ Clear these on workspace switch BEFORE making new request.
